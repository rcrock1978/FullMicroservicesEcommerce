Root Cause Analysis

Based on my review of the sync job code, I believe the most likely cause is that the SOAP API call (GetAllSafes) returned an empty or malformed response. This could be due to an access or connectivity issue between ServiceNow and the CyberArk API.

When the API returns no safes, the sync logic interprets this as "all safes have been removed" and deactivates every record in the ServiceNow table.

var response = JSON.parse(logic.GetAllSafes());  // ← Could fail or return empty

Proposed Safeguards

# Safeguard Purpose
1 Validate API Response Abort the sync if the API returns an empty or null response
2 Minimum Threshold Check Abort the sync if the number of safes returned falls below a defined minimum
3 Deactivation Percentage Cap Limit the number of records that can be deactivated in a single run (e.g., max 20%)
4 Try/Catch Error Handling Catch and log unexpected errors to prevent uncontrolled behavior

These safeguards work together to provide defense-in-depth, ensuring that no single point of failure can trigger a mass deactivation.
